UX deep dive · goodvibes-desktop v1.1.4 · July 6, 2026

Strong bones, unfinished nervous system

Fifteen reviewer agents read the app end to end across ten UX dimensions; seventeen high-stakes claims were re-verified by adversarial agents against the source, and the app was built and run live for screenshots of both a fresh first-run and real data. The verdict: the visual design, component consistency, and data engineering are genuinely good — but the app repeatedly builds a capability and then fails to connect it, and the core loop (a running Claude terminal) fails silently in the moments that matter most.

The one-paragraph diagnosis

GoodVibes' single biggest UX problem is not any one screen — it's a pattern. At least eleven fully built features exist in the codebase and are never wired to anything: an onboarding wizard, a notification center, a loading-progress overlay, a full-text session search engine, terminal search, screen-reader announcements, a rich error-recovery UI, session titles/summaries, tag filtering, the theme toggle, and per-project budget/permission settings. Each one looks finished in the UI or the code, so users (and future maintainers) trust it — and each one silently does nothing. Paired with a core loop that hides failure (terminal tabs vanish without explanation, the whole app quits without warning while sessions run), the app currently under-delivers its own engineering. The fastest route to "zero friction" is not new features: it's wiring or deleting what's already there, and making every failure loud.

What already works Keep these — several are better than the ecosystem norm

Cost math is trustworthy

No double-counting: four disjoint token buckets, per-message dedup by sha256(messageId|requestId), and a dated pricing history so old sessions are costed at the price in effect at the time (pricing-fetcher.ts:260-347). The scary-looking $7,971 / 11.95B totals are real cumulative billing, just unexplained in the UI.

Four feature views are perfect twins

Hooks, Skills, Agents, Commands share one header/empty-state/confirm-dialog/spinner language. Learn one, know all four.

Settings survive corruption

Field-level validation recovers bad settings individually and tells the user exactly which fields were reset (settingsStore.ts:243-251). Migrations were hardened after a real bug, with the lesson documented in code.

First-run welcome screen

Clean hero, four clear actions, a disabled state with explanation, and a keyboard hint. Verified live with a fresh HOME.

Zero-setup GitHub sign-in

Device flow ships a default client ID, with a polished code/countdown UI. (An earlier reviewer claim that this was broken was refuted on verification.)

Dirty-tree checkout guard, no force-push

Branch switching with uncommitted changes gets a real explain-and-confirm modal; force-push simply doesn't exist in the UI.

Performance fundamentals

No sync IPC anywhere, watchers debounced, big lists virtualized, PTY analyzer buffer bounded, window shown only on ready-to-show.

Crash containment

Layered error boundaries: a crashing view or terminal shows a scoped, retryable fallback ("Other terminals are unaffected") instead of a white screen.

One-click session resume

Session rows resume straight into a terminal via --resume with ID validation. Claude binary auto-discovery covers the stripped-PATH desktop-launch case.

Theme 1 — The core loop hides failure A terminal app must never lose a terminal silently

Critical Verified A terminal tab vanishes with zero notice when its process exits or crashes

The main process sends terminal-exit with the exit code; the renderer's only listener discards the code and silently deletes the tab (useIpcListeners.ts:65-71). If Claude crashes mid-task, the tab just disappears — no toast, no exit code, no last output, no restart-in-place.

Fix: keep the tab in a dimmed "exited (code N)" state with Restart / Close actions. Only user-initiated close removes immediately.

High Verified Closing a tab kills the process instantly — hover-reveal X, no confirmation, no undo

The close button (visible only on hover) calls killTerminal directly (TerminalHeader.tsx:171-187). A misclick during a long agent run kills it outright.

Fix: confirm (or toast-undo) when the session looks busy — the PTY stream analyzer already tracks activity.

High Closing the window kills every running session with no warning — and there's no tray

window-all-closed → graceful shutdown → force-kill terminals + tmuxService.cleanup(). before-quit never checks getTerminalCount() (shutdown.ts). One accidental close ends all active work.

Fix: "You have N running sessions — quit anyway?" plus an optional close-to-tray.

High Verified tmux settings promise "persistence" — but the app kills tmux sessions on quit

The setting copy says sessions are wrapped in tmux "for persistence and external access" (TmuxSettings.tsx:44); shutdown.ts:97-99 unconditionally runs tmux kill-session on quit. The feature's headline benefit does the opposite of what it says.

Fix: detach instead of kill on quit (offer kill as an explicit action), or correct the copy.

High Verified If the Claude CLI is missing, the primary button is a dead end

No pre-flight check. Either a generic "Terminal Error" toast that deliberately drops the real error string (terminalStore.ts:63-112), or the tab flashes and silently vanishes via the exit path above. No "install Claude Code" guidance anywhere.

Fix: startup probe → persistent banner with install link; include result.error in the toast; special-case fast nonzero exits ("Claude exited immediately — is it installed and logged in?").

Medium No tab restore after restart; tabs can't be renamed or reordered; terminal has no search UI

Only a single-session "Quick Restart" exists. Tab names are frozen at the folder basename, indistinguishable across worktrees. @xterm/addon-search is loaded but nothing ever calls it — Ctrl+F does nothing (TerminalInstance.tsx:245-249).

Fix: persist open-tab layout (cwd + resume ID) with a "Restore N tabs" offer; double-click-to-rename; wire the already-loaded SearchAddon to Ctrl+F.

Theme 2 — The keyboard is broken exactly where users live Focus is in a terminal ~90% of the time; that's where shortcuts die

Critical App shortcuts don't fire while a terminal has focus

The global handler skips every non-global shortcut when focus is in an input — and xterm's hidden textarea counts (useKeyboardShortcuts.ts:550-558). Only the palette, quick switcher, help, and escape are global. Next/prev tab, new terminal, zoom, and all Ctrl+1–9 view switches are dead in the app's default state.

Fix: mark app-level navigation shortcuts global: true, or exempt the xterm helper textarea from the "user is typing" heuristic.

Critical xterm swallows Ctrl+Tab, Ctrl+K, Ctrl+N, Ctrl+3–8 — and leaks them into your shell

Independent of the bug above: xterm cancels these at the textarea before the app ever sees them, sending control codes to the shell instead (Ctrl+K = kill-line, Ctrl+N = next-history). Fixing the first bug alone won't restore them.

Fix: attachCustomKeyEventHandler in TerminalInstance.tsx to preempt app-reserved combos — or move to combos terminals don't reserve (Ctrl+PageUp/PageDown for tabs).

High Three surfaces advertise shortcuts that don't exist

Settings' hardcoded list claims Ctrl+W (close tab) and Ctrl+F (terminal search) — neither is implemented (KeyboardSettings.tsx:11-20). The command palette fabricates Ctrl+10…15 hints and a fictitious Ctrl+, (CommandPalette.tsx:39-73). The QuickSwitcher's own footer says "Ctrl Tab" when the real binding is Ctrl+K. A real, customizable shortcut registry with conflict detection already exists — none of these surfaces read from it.

Fix: derive every displayed hint from the shortcut registry. Delete the static Settings list.

Medium Palette & QuickSwitcher lack focus traps and dialog semantics; a11y infrastructure is unused

The two most-used overlays are the only modals not wrapped in the app's own FocusTrap, with no role="dialog". useAnnounce() has zero call sites; ~56 icon-only buttons have no accessible name; no prefers-reduced-motion rule exists across 112 animated files.

Fix: copy the proven KeyboardShortcutsPanel pattern; one global reduced-motion rule; an aria-label sweep.

Theme 4 — The UI tells untruths Copy and state that contradict what the code does

Critical The Memory view never touches your real CLAUDE.md files

The view says "CLAUDE.md files provide persistent instructions for Claude" and shows user/project/local files — but saves go to the app's internal knowledge_entries SQLite table, never to disk (useMemoryFiles.ts:43-219). A user "saves" instructions, sees success, and Claude never sees them. The real file I/O exists in contextInjection.ts, unconnected.

Fix: read/write the real files (like Hooks/Skills/Agents already do), or label it a draft area with an explicit Apply step. Interim: a one-line disclaimer.

High The Live Monitor contradicts itself by design

"Live Sessions" counts any Claude activity machine-wide in the last 5 minutes; the Idle pill counts this window's terminals; "Uptime" is a component-local counter that resets to 0s on every view switch; three live rows can render pixel-identical labels (MonitorPanel.tsx). Seen live: "27 Live Sessions · 0 Terminals · Idle · 0s Uptime".

Fix: relabel to what each number measures, add a distinguishing suffix per live row, use real process uptime or drop the stat.

Medium Analytics is polluted and unexplained

Ephemeral workflow/worktree dirs (wf_*) appear as peer "projects" in Cost-by-Project; cumulative token totals (300M+ per session, legitimately) get no framing, so correct numbers read as bugs. Cache pricing is scraped per-model, then discarded for hardcoded multipliers that only coincidentally match.

Fix: roll temp paths into an "Ephemeral" bucket, add a "cumulative across N API calls" caption, use the scraped cache rates.

Medium Naming drift: "Notebook" vs "Knowledge", "Commands" vs "Skills"

The menu says Notebook; the table, IPC methods, and the repo's own e2e map still say Knowledge (the e2e nav entry is dead). Commands and Skills are two skins over the identical skills IPC/table — they will drift. The Commands view reuses the Terminal icon.

Fix: one mechanical rename; give Commands/Skills distinct backends (they are distinct Claude Code concepts) and a distinct icon.

Theme 5 — Startup: the window waits on everything The whole init chain runs before anything appears

Critical Verified Window creation is serialized behind DB init, sync file backups, a full ~/.claude/projects walk-and-parse, and an un-timeout-bounded GitHub network call

initialization.ts:34-127 awaits everything — including initializeGitHub() whose verifyToken fetch has no AbortController (a captive portal can hang launch for a minute+) — before createWindow(). The progress events for the import are sent to a window that doesn't exist yet and are silently dropped. Big history + slow disk = a long, indistinguishable-from-crashed blank launch.

Fix: create the window after DB + IPC registration only; stream the existing scan-status events into the already-built LoadingOverlay; 3–5s timeout on token verification and reconcile in the background.

Medium Three overlapping watchers poll the same session tree forever

An fs.watch watcher (good) plus a 2-second full recursive re-walk in main plus a 10-second full re-walk while SessionsView is open — continuous background I/O that grows with the session history the app encourages you to accumulate.

Fix: let fs.watch drive updates; keep a single 60s safety-net poll.

High Verified Every view switch destroys state — including terminal scrollback

Only the active view is mounted (MainContent.tsx:207-214). Filters, search text, file-manager path, and selections reset on every switch; xterm instances are disposed, so glancing at Analytics wipes the build output you were reading. The team already solved this pattern for terminal tabs (keep mounted, toggle visibility) — it just isn't applied at the top level.

Fix: keep Terminal (at minimum) permanently mounted; lift view filter/search state into small persistent store slices.

Theme 6 — Destructive actions without guardrails

High File manager deletes files and whole directories with zero confirmation

Context-menu Delete calls deleteFile/deleteDirectory (recursive) immediately (FilesView/index.tsx:272-285) — on real home-directory paths. Six other views use a styled danger confirm; this one has nothing.

Fix: same useConfirm pattern; typed confirmation for directory deletes.

High Installing a built-in silently overwrites your custom hook/skill/agent/command of the same name

writeMarkdownFile/writeHookScript write unconditionally, no existence check (features.ts:73-97).

Fix: existsSync guard → overwrite confirm (the install modals already exist to host it).

High Merge-conflict "resolution" is two hover-revealed buttons that discard content

Whole-file Ours/Theirs only — no diff of the conflicting hunks, no open-in-editor path, no hint that partial resolution isn't supported (GitConflicts.tsx). The highest-stakes git moment gets the least information.

Fix: show conflict hunks (the diff modal already exists) + an explicit "open in editor" action before the side-pick buttons.

High A corrupt goodvibes.db locks you out of the app — and it's the one file never backed up

No try/catch, no integrity check around DB open/migrations; failure → opaque error box → quit. Raw (replaceable) session JSONLs are diligently backed up; the DB holding irreplaceable curation (tags, notes, titles, collections) is not. WAL mode + force-kill on quit raises exactly this corruption risk. Old builds also silently open newer-schema DBs.

Fix: PRAGMA quick_check + quarantine-and-offer-restore on failure; periodic DB backups; explicit newer-schema message.

Theme 7 — Papercuts worth batching Each small; together they set the app's feel

  • Literal "clipboard" renders instead of 📋 in the Activity Feed empty state — MonitorPanel.tsx:153 types the string instead of the icon map lookup used four lines down. Seen live in both fresh and real environments.
  • Git errors use native OS alert()/confirm() for commit/push/pull failures and single-file discard — raw git plumbing text in OS chrome, while the same panel has styled modals for everything else.
  • First push of a new branch fails with a raw "no upstream branch" error and no retry — bare git push, no -u fallback.
  • Detached HEAD shows literal HEAD (no branch) with no explanation or "create branch from here" rescue.
  • No "Stash & Switch" in the dirty-checkout modal — the safe choice takes five manual steps; the destructive one takes one click.
  • "Skip Permission Prompts" (i.e. --dangerously-skip-permissions) is styled identically to cosmetic toggles.
  • Permission modes have three vocabularies across Settings / Project Registry / Agent templates; only the agent one is actually consumed at runtime.
  • 54 settings in 16 always-expanded sections, no search, no per-setting reset (only nuke-all), no export/import. Timezone defaults to UTC instead of the system zone.
  • Toast overflow is invisible: beyond 3 stacked toasts, the rest render at opacity 0 and expire unseen — batch failures are unreviewable (and the empty notification center can't catch them).
  • "Empty" and "failed to load" are indistinguishable in all 8 feature views — a transient IPC error renders "create your first one!"
  • Plugins' Installed tab has no search; Files/Project Registry use plain text where six other views use the shared spinner.
  • goodvibes:// deep links are dropped on cold start on Windows/Linux (argv never inspected); single window only; no auto-update or even an update-available check (publish: null, portable formats).

Theme 8 — A contributor can't run it Found empirically, not by agents

High Fresh clone fails at install, can't launch, and typecheck reports 902 errors

No engines field, no version pin anywhere: on current Node 26, better-sqlite3 fails to compile (V8 API drift) and npm install dies. After installing under Node 22, the app still can't launch — native modules are built for Node's ABI (127) while Electron 39 needs 140, and there is no electron-rebuild step, postinstall, or doc (npmRebuild: false). And npm run typecheck fails with 902 errors because no window.goodvibes type declaration exists anywhere — there is no .d.ts for the entire preload bridge. The e2e suite couldn't launch the app for the same ABI reason.

Fix: add engines + .nvmrc; add @electron/rebuild as a postinstall; write the preload bridge .d.ts (this also restores type safety across 880 currently-unchecked call sites); make CI run install→typecheck→e2e from scratch.

The roadmap Ordered by trust recovered per unit of effort

P0 · STOP LYING, STOP LOSING WORK — days, not weeks

Make every failure loud and every destructive action guarded

  • Terminal exit → visible "exited" tab state with code + Restart (kills the worst silent failure).
  • Quit guard when sessions are running; confirm on busy-tab close; Files delete confirmation; install-overwrite guard.
  • Memory view: disclaimer now, real CLAUDE.md file I/O next.
  • Hide the tag filter stub; fix the theme toggle; remove or wire the inert per-project budget/permission fields.
  • One-liners: the "clipboard" string, QuickSwitcher hint, fabricated palette hints, tmux copy.
P1 · THE DAILY DRIVER — the two flows a user touches every hour

Startup and keyboard

  • Show the window after DB init only; stream scan progress into the existing overlay; timeout the GitHub fetch.
  • Make navigation shortcuts global + attachCustomKeyEventHandler so tabs/views/palette work from inside a terminal (where users actually are).
  • Keep the Terminal view mounted across navigation (scrollback survives); persist per-view filter state.
  • Derive all shortcut hints from the registry — one source of truth.
P2 · WIRE OR DELETE — the ledger above, item by item

Finish what's built before building more

  • Highest yield: FTS search behind the search box, session titles/summaries backfill, notification bell fed by real events (which also fixes toast overflow), onboarding wizard behind a first-run flag.
  • Delete honestly: ErrorRecovery.tsx, defaultFilterLogic, the static shortcuts list, dead e2e nav entries.
P3 · STRUCTURAL BETS — schedule deliberately

Durability and reach

  • DB integrity check + backups + recovery dialog; update-available check (then electron-updater).
  • Tab-layout restore after restart; tray / close-to-tray; multi-window or per-project workspaces.
  • Conflict resolution with real hunks; a11y pass (focus traps, labels, reduced motion, announcements).

Method

Multi-agent workflow: 10 dimension reviewers (first-run, navigation/IA, terminal, sessions/analytics, git/GitHub, settings, feedback/errors, perceived performance, feature-view consistency, keyboard/a11y) reading source directly with file:line citations; every critical/high claim re-examined by an independent adversarial verifier instructed to refute it (16 confirmed, 1 refuted — the GitHub OAuth zero-setup path, which works via a bundled device-flow client ID); a completeness critic sweeping for missed areas (it found the DB-corruption, update, tray/quit, and deep-link issues). Live evidence: the app was built and launched under Playwright twice — once with a fresh HOME (true first run) and once against real data — producing screenshots of both. Empirical checks: fresh-clone install on Node 26 and 22, typecheck, build, and the repo's own e2e suite. Roughly 2.1M agent tokens, 870+ tool calls, 593 source files in scope.
